## Requirements

### R1. Data Pipeline с корректным temporal split

Реализовать загрузку датасета MovieLens-1M и его обработку. Разбивка на train/validation/test **обязана** быть **temporal** (по времени выставления рейтинга): для каждого пользователя последние взаимодействия уходят в test, предпоследние — в validation, остальные — в train. Random split запрещён — он создаёт data leakage. Фильтровать пользователей с менее чем 5 рейтингами.

### R2. Двухэтапный recommendation pipeline

**Этап 1 (Retrieval):** обучить модель для генерации user- и item-эмбеддингов с использованием **in-batch negative sampling** (не random negatives). Модель должна поддерживать векторный поиск по предварительно индексированным item-эмбеддингам для получения топ-200 кандидатов за запрос. Индекс должен **пересобираться** при каждом переобучении модели (версионирование эмбеддингов).

**Этап 2 (Re-ranking):** обучить модель градиентного бустинга для переранжирования 200 кандидатов из Этапа 1 в финальный топ-10. Обучающая выборка для re-ranker должна включать **минимум 8 признаков** (пользовательские, айтемные и пользователь-айтем совместные). Позитивные примеры — рейтинги >= 4, негативные — из кандидатов Этапа 1, которые не были оценены.

### R3. Cold-start поддержка и устойчивость API

API должен корректно обрабатывать **два случая cold-start**:
- `user_id` не существует в обучающих данных → вернуть контентные рекомендации на основе текстовых эмбеддингов описаний фильмов (без краша).
- `item_id` не существует → пропустить или вернуть graceful ошибку (HTTP 404, не 500).

Любой запрос к `/recommend/{user_id}` должен возвращать ответ за <= 500 мс на CPU.

### R4. Offline-метрики на held-out тест-сете

Реализовать скрипт `evaluate.py`, который считает **Precision@10, Recall@10, NDCG@10** на тест-сплите (не на train, не на validation). Скрипт должен выводить результаты в JSON и сравнивать минимум **три модели**: (1) popularity baseline, (2) retrieval-only, (3) full two-stage pipeline. Метрики должны воспроизводимо пересчитываться при каждом запуске.

### R5. HTTP-сервис и интерактивный UI

Развернуть HTTP API (endpoint `POST /recommend` или `GET /recommend/{user_id}`) и веб-интерфейс. UI должен позволять выбрать любого пользователя из датасета и показывать его историю просмотров рядом с персонализированными рекомендациями. Рекомендации для **разных пользователей** должны **различаться**. Весь стек запускается одной командой (`docker compose up` или аналог).

### R6. Тесты и документация

Покрыть unit-тестами минимум следующие компоненты: temporal split логика, feature engineering (проверить что фич >= 8), cold-start fallback (оба случая), API endpoint `/recommend`. README должен содержать: схему архитектуры, таблицу метрик (результаты evaluate.py), инструкцию запуска.

## Acceptance Criteria

### Корректность данных
- [ ] Ни один рейтинг из тест-сета не присутствует в train-данных (нет data leakage)
- [ ] Пользователи с < 5 рейтингами отфильтрованы
- [ ] Все три сплита непересекаются

### Качество модели (на тест-сете)
- [ ] Retrieval Recall@200 >= 0.40 (200 кандидатов покрывают >= 40% релевантных айтемов)
- [ ] Full pipeline NDCG@10 >= 0.20
- [ ] Full pipeline Precision@10 >= 0.15
- [ ] Full pipeline NDCG@10 строго выше, чем retrieval-only NDCG@10 (re-ranker добавляет ценность)
- [ ] Full pipeline NDCG@10 строго выше popularity baseline NDCG@10

### Устойчивость
- [ ] `GET /recommend/999999` (несуществующий user) → HTTP 200 или 404, **не 500**
- [ ] `GET /health` → HTTP 200 в течение 2 секунд после старта
- [ ] Latency `/recommend` <= 500 мс (измерить через `curl -w "%{time_total}"`)

### Воспроизводимость и инфраструктура
- [ ] `docker compose up` поднимает все сервисы без ошибок
- [ ] `python evaluate.py` выводит JSON с метриками без ошибок
- [ ] Повторный запуск `evaluate.py` даёт те же метрики (детерминизм через seed)
- [ ] Feature count >= 8 (проверяется тестом или логом feature importance)
- [ ] FAISS-индекс пересобирается при запуске train-скрипта (не переиспользуется старый)

### Документация
- [ ] README содержит таблицу метрик с реальными числами из `evaluate.py`
- [ ] README содержит ASCII/Mermaid схему архитектуры pipeline
- [ ] `docker compose up` инструкция работает с нуля (без предустановленных зависимостей кроме Docker)
