# RecSys Two-Tower

![Python 3.10+](https://img.shields.io/badge/python-3.10+-blue.svg)
![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)

Двухэтапные рекомендации фильмов на MovieLens-1M: two-tower retrieval в FAISS и CatBoost, который переставляет топ-200. Сервис — FastAPI, интерфейс — Vite.

## Архитектура

Пользователь запрашивает рекомендации у FastAPI. Пайплайн считает вектор пользователя, достаёт из FAISS 200 ближайших фильмов, которых нет в истории, и CatBoost оставляет топ-10.

Башни симметричные, на выходе L2-норма, индекс — FAISS inner product.

- Башня фильма: `item_id`, multi-hot жанров и год из названия.
- Башня пользователя: `user_id`, средние жанр и год последних 10 фильмов из train и среднее их id-эмбеддингов.
- Обучение: in-batch InfoNCE и 8 popularity-sampled негативов. Вероятность фильма пропорциональна числу его оценок в train. Поправку logQ этот лосс не вычитает, так что модель не дебайесится относительно распределения сэмплинга.
- Ранкер: CatBoost YetiRank. Итоговый скор — порядок FAISS плюс остаток модели. Вес остатка подбирается на отложенных пользователях. Отдельный признак `recent_neighbor_score` — косинус кандидата со средним вектором последних фильмов.

GNN и мультимодальные энкодеры в репозитории есть, но в этот индекс не пишут.

## Offline-метрики

Сплит — leave-last-out внутри пользователя, не общий срез по времени: в train одного пользователя могут лежать события позже теста другого. Последнее взаимодействие — test, предпоследнее — validation, остальное — train. Пользователи с менее чем 5 оценками отброшены.

После этого остаётся 6040 пользователей, у каждого одно тестовое событие. В среднее входят 3563, у кого эта оценка не ниже 4. Остальные 2477 из метрики выкинуты, а не записаны нулём: иначе каждое число в таблице умножилось бы на 3563/6040. У пользователя в оценке один позитив, поэтому Precision@10 остаётся маленьким.

Таблица округлена из [reports/metrics.json](reports/metrics.json). Это прогон `evaluate.py` на коде `79982d0`, seed 42 у two-tower и у CatBoost. Локальный `metrics.json` в git не входит.

| Popularity Baseline | 0.0022 | 0.0222 | 0.0104 | 0.0070 |

## RP3beta и co-visitation

Это эксперимент на ветке, не новый путь по умолчанию. Граф и матрица co-visitation построены только по train того же leave-last-out. В тесте 3563 пользователя с оценкой не ниже 4. Параметры выбраны по recall@200 на 1000 таких пользователях из validation, seed 42, и только потом посчитаны на всём тесте. Полный прогон — [reports/rp3_metrics.json](reports/rp3_metrics.json), команда `python scripts/rp3_bench.py`.

RP3beta — один переход item→user→item: `P_ui^alpha` и `P_iu^alpha`, затем столбец делится на `popularity^beta`. Глубины 2 нет. Лучшая пара на validation: `alpha=1`, `beta=0.7` (recall@200 = 0.586). Co-visitation — пары из одной train-истории с весом `exp(-|Δt| / τ)` и BM25 по популярности назначения. Лучшее на validation: `τ=7` дней, `k1=2`, `b=0.25` (recall@200 = 0.432).

| источник | recall@50 | recall@200 | recall@1000 | доля уникальных @200 |
|---|---:|---:|---:|---:|
| two-tower | 0.2621 | 0.4920 | 0.7648 | 0.779 |
| RP3beta | 0.2874 | 0.5902 | 0.9130 | 0.283 |
| co-visitation | 0.1937 | 0.4423 | 0.8204 | 0.346 |
| two-tower ∪ RP3 | 0.4443 | 0.7348 | 0.9596 | размер 360 |
| two-tower ∪ co-vis | 0.3831 | 0.6792 | 0.9408 | размер 373 |
| все три | 0.4825 | 0.7592 | 0.9646 | размер 429 |

Доля уникальных — какая часть топ-200 источника не входит в топ-200 остальных, среднее по пользователям. Размер объединения — среднее число фильмов в объединении топ-200.

Реранкер заново учится на объединении топ-200. К признакам CatBoost добавлены скор, ранг и флаг каждого источника. Базовый prior по-прежнему ранг FAISS, у фильма вне топ-200 two-tower он равен 200. Повторное обучение одного two-tower нужно, чтобы отделить новый источник от шума CatBoost.

| модель | NDCG@10 | Recall@10 | MAP@10 |
|---|---:|---:|---:|
| текущий пайплайн, тот же артефакт | 0.0867 | 0.1659 | 0.0627 |
| two-tower, обучен заново | 0.0852 | 0.1645 | 0.0612 |
| two-tower + RP3 | 0.0979 | 0.1847 | 0.0716 |
| two-tower + co-vis | 0.0878 | 0.1631 | 0.0650 |
| все три | 0.0952 | 0.1813 | 0.0691 |
| retrieval-only | 0.0430 | 0.0957 | 0.0274 |
| RP3 без реранкера | 0.0416 | 0.0848 | 0.0287 |
| co-vis без реранкера | 0.0299 | 0.0643 | 0.0197 |

Построение RP3 — 1.02 с, скоринг 6040 пользователей — 2.04 с. Co-visitation строится 19.0 с и считается 2.13 с. Полный цикл текущего `recommend` на 3563 пользователях — 111.4 с, это признаки и CatBoost по одному пользователю, не поиск кандидатов. Two-tower по всему каталогу — 0.52 с.

Те же две модели переучены на сидах CatBoost 42, 43, 44, 45 и 46. Списки кандидатов не менялись. NDCG@10 two-tower+RP3: 0.0979, 0.0966, 0.0961, 0.0979, 0.0966, среднее 0.0970. Парная разница с two-tower того же сида: среднее +0.0097, 95% интервал Стьюдента `[0.0061, 0.0133]`. Разница с зафиксированным опубликованным 0.0867: среднее +0.0104, интервал `[0.0094, 0.0114]`. Худший RP3-сид (0.0961) выше лучшего two-tower-сида (0.0905). Бутстреп 10 000 выборок пользователей на сиде 42 даёт для разницы с опубликованным пайплайном интервал `[0.0068, 0.0156]`. Ни один из этих интервалов не содержит ноль. Прогон — `python scripts/rp3_seed_sweep.py`, числа в [reports/rp3_seed_sweep.json](reports/rp3_seed_sweep.json).

RP3beta как второй источник кандидатов поднимает NDCG@10 примерно на 0.010. Сам по себе RP3 слабее retrieval-only (0.0416 против 0.0430), так что башню он не заменяет. Co-visitation хуже two-tower на recall@200 и втроём не лучше пары two-tower+RP3.

В выдаче RP3 выключен. `retrieval.rp3.enabled` по умолчанию `false`, и список кандидатов остаётся списком FAISS. Включённый флаг объединяет топ-200 FAISS с топ-200 RP3, построенным только по train; фильм только из RP3 получает `retrieval_rank` 200. Скор, ранг и флаг источника добавляются лишь тогда, когда загруженный CatBoost уже обучен с этими колонками. Опубликованный `.cbm` их не содержит, поэтому флаг при старых весах не ломает схему модели и не даёт 0.0979: это число — повторное обучение при включённом флаге, его веса в репозиторий не входят. Co-visitation в конфиге и в выдаче нет, только в офлайн-прогоне.

## Запуск

Нужны Python 3.10+ и Node.js. Датасет и веса в репозиторий не входят.

```bash
pip install -e ".[dev]"
python -m src.data.download
make train
make serve-api
make serve-ui
```

`make train` учит two-tower, затем CatBoost и перезаписывает `metrics.json`. API поднимается на `http://localhost:8000`, UI Vite — на `http://localhost:5173` и ходит в API за `http://localhost:8000`.

Полезные ручки: `GET /health`, `GET /recommend/{user_id}`, `GET /history/{user_id}`, `GET /metrics`.

## Разработка

```bash
make install
make test
make lint
```

`make install` ставит Python-пакет и зависимости UI. `make serve-api` и `make serve-ui` — отдельные цели.
